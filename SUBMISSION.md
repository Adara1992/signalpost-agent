## One run command

```bash
./run.sh
```

This creates a venv, installs `requirements.txt`, downloads the public
Brønnøysund bulk snapshot if not present (`data/brreg-enheter.csv`), and
runs the 100-company smoke batch. For the official batch:

```bash
BULK=data/brreg-enheter.csv EXPECTED_COUNT=1000 RUN_ID=official \
  ./run.sh /path/to/official-batch.jsonl out-official
```

Requires Python 3.12+. No API keys, no model keys, no credentials of any
kind. Expected cost per official run: **$0** (all sources are free public
endpoints; ~6–7 HTTP requests per company).

## What the agent does

Modules (default `--modules`):
`registry, accounting_obligation, registry_live, financials, roles, group,
locations, website, news, site_activity, synthesis`.

- **Registry core (high precision):** identity anchored in the frozen
  Brønnøysund bulk snapshot; live registry check; official financials
  (newest 3 filings, latest year first), roles, group links, registered
  workplaces. Every field carries source URL, retrieval time and content
  hash; one terminal JSONL envelope per company, including
  `not_available` / `ambiguous` / `blocked` / `failed` states. Missing
  values are never turned into zeros — a material wrong-company match is
  avoided by returning `ambiguous` / `not_available` instead of guessing.
- **Website:** fetches the registry-listed company site through an
  SSRF guard (literal IPs, localhost and private ranges blocked; the
  sandbox egress-proxy CGNAT range 198.18.0.0/15 is allowed only for
  DNS-resolved hostnames).
- **News (dated activity):** Google News RSS, keyless, 1 request/company.
  Headline gate requires the distinctive name tokens consecutively
  (legal-form tokens dropped, Norwegian possessive -s tolerated; a
  single-token brand needs a lowercase continuation so "Aneo" cannot
  match "Aneo Roan Vind Holding AS"). Items are published with title,
  publisher, publication date and source URL, marked honestly
  `verification: "rss_headline"` — the claim is exactly what Google News
  reported. No article body is claimed: Google News article links do not
  resolve reliably from an automated fetcher (interstitial / HTTP 400),
  so fetching them would burn budget for zero evidence.
- **Site activity:** mines already-fetched company-site pages for dated
  news lines and job titles — zero extra requests.
- **Synthesis:** deterministic template summary from verified facts only
  (industry, latest financials with period, leadership, locations,
  website, news, hiring, changes), with explicit unknowns. No model.

## Models / APIs / licences

- **Models: none.** The agent is fully deterministic; no LLM is used
  anywhere in the run path.
- **APIs / sources (all free, public, no key):** Brønnøysund
  Enhetsregisteret (bulk CSV + live API), Regnskapsregisteret financials,
  Google News RSS, registry-listed company websites.
- **Licences:** this agent's code is MIT (see LICENSE). Dependencies are
  pinned in `requirements.txt` (beautifulsoup4, extruct, lxml, pydantic,
  pypdf, tldextract, trafilatura — all permissive open-source licences).
- **Data rights:** only public registry data and public news headlines
  are used. No scraped LinkedIn data, no NAV jobs feed, no social
  scraping. The kit's quarantined connectors were not used.

## Known limitations (honest)

- The kit's own baseline is ~34/100; this entry adds the news,
  site-activity and synthesis modules on top of a high-precision registry
  core. Qualification (≥65/100 and ≥95% precision) is a stretch but
  plausible; recall on the 1,000-company official batch will be dominated
  by registry coverage, with news contributing mainly for larger firms.
- Brand-name shortening is not handled: "DNB BANK ASA" headlines say
  "DNB", so the strict headline gate misses them. The strict gate is
  kept deliberately — precision first.
- Google News RSS returns at most ~45 items per query and a 2-year window.
